# 神经评分器数据审计、清洗与针对性标注建议

日期：2026-11-26。提交人：Jun040504。状态：**待全组评审可执行性，尚未实施**。

## 1. 为什么提出本建议

当前问题是神经评分器能否把任务总分正确归因到购物动作，而非仅能拟合终局总分。终局 MSE 只约束逐步分数之和，不能唯一确定每一步的贡献。数据质量、监督信号和评分时机均可能影响结果，尚不能认定某一项是唯一原因。

截至本建议编写时，#57 的设备结果回报显示：独立 dev 的 32 个方向有效对中，stage126 为 20/32，terminal 与 ranking 均为 21/32；ranking 相对 terminal 没有提高排序正确率。38 对的总分 MSE 分别约为 0.120542、0.126346、0.125994，7544 的打开商品步排序仍反向。这些是设备回报，本 PR 不替代 Qiu 的原件独立验收，也不宣告神经方案已通过或可以接入 PPO。

## 2. 建议范围和优先级

先做“错误审计＋针对性标注”，不直接大规模删除或改写数据。本 PR 仅增加建议文档；不修改 SFT 数据、PRM 训练输入、划分、模型、损失或 PPO 实现，不申请新增 GPU 训练预算。

| 优先级 | 建议 | 要解决的问题 |
|---|---|---|
| P0 | 追溯样本身份、错误类型和信息可见性 | 区分数据错误、真实购物失败和评分时机问题 |
| P0 | 技术异常隔离、真实负例保留 | 避免将坏日志当负例，或把有价值的失败删掉 |
| P1 | 同前缀分叉与动作位置的证据标注 | 明确比较的动作、可用信息和环境分差 |
| P1 | 分开审计终局拟合与排序信号 | 判断新增排序监督是否实际产生有效梯度和分差 |
| P2 | 小规模训练侧试点后再冻结实验 | 根据结果决定补采样、调整监督或暂不继续训练 |

## 3. 建议标注字段

建议使用独立 JSONL 旁表，通过原始文件 SHA 和轨迹 ID 关联；保留原始数据不覆盖。以下是拟议标注契约，尚不是已支持的训练输入接口。

| 字段 | 内容与约束 |
|---|---|
| schema_version、annotation_id | 标注版本与唯一编号 |
| task_id、trajectory_id、pair_id | 任务、轨迹及可选比较对身份；同一任务多轨迹可分别追踪 |
| source_commit、source_path、source_sha256 | 原件来源与不可变身份；标注表另存自身 SHA |
| split、historical_usage、b1_sft_exposure | 原划分、历史训练/调参/诊断使用记录，以及继承 B1 的 SFT 暴露；未知须明确记录 |
| goal_fingerprint、instruction_fingerprint | 采用冻结脚本归一化；记录脚本版本，检查跨划分重复 |
| error_types | 类别、价格、规格/选项、检索、格式/非法动作、循环/预算、技术异常、其他、无法判断；允许多选 |
| requirement_evidence | 每项要求的原文、页面/轮次、证据片段及是否满足；无法判断不强填 |
| information_available_at | 点击前已可见、点击后才可见、全程不可见或未知；逐项要求记录 |
| action_turn、action_text、score_token_index | 被评动作、轮次、实际 tokenizer 结束位置；同时注明索引约定和输入 SHA |
| prefix_sha256、branch_input_sha256 | 共享前缀及两臂实际输入；允许动作长度不同，但不能混入下一轮观察 |
| terminal_reward、termination、done、full_success | 保留真实连续终局分、结束原因与购买/满分成功区别，不把 done 当作成功 |
| pair_reward_gap、pair_status | 同环境重放的真实分差；严格不同分、同分、不可比较分别记录 |
| disposition、reason_code | 保留、隔离、待复核及原因；技术异常不得混入正常零分 |
| annotators、adjudication、label_source | 标注者、争议裁决、标签来源；区分人工判断和环境终局分 |

动作索引必须由实际 Qwen 模板与 tokenizer 定位，核对非 padding 的 assistant 结束 token。点击后商品详情属于后续观察，不能偷偷加入点击前评分输入。若比较“看到详情后的判断”，应单独定义评分位置、样本和实验，不能与原动作分数混为同一机制。

终局高低分只表示两条完整轨迹的结果差异，不自动等价于每个中间动作的真实贡献。人工错误类型用于诊断；未经协议确认，不直接变成奖励或步级训练标签。

## 4. 清洗规则

- 保留真实的类别、价格、规格错误和正常 max_steps 失败；它们可能是重要负例。不得为了降低 MSE 删除困难样本。
- 原件损坏、关键观察缺失、重放技术失败、身份不一致、错配比较对和标签矛盾进入隔离表；原件保留，修复或排除理由可审计。
- 同前缀比较对必须核对同一环境身份、共同历史及预定后续动作策略；记录两臂真实终局分。非首个分叉的后续变化也要披露，不能将所有终局差异归因于首次点击。
- 保留 0、部分分与满分的真实环境分；正常预算耗尽的零分不是技术故障；购买结束也可能是零分或部分分。
- 同分对单列，不制造高低标签；无法验证的标签标为未知，不凭模型预测补标签。
- 不截断掉关键动作或结果后仍沿用完整轨迹标签。超长样本单列覆盖情况，处理策略另行预登记。
- 所有保留/隔离记录均有唯一 ID、原因和计数；原始总数应等于各处置类别数之和。

## 5. 最小试点与验收建议

以下数量是供评审的工作量上限，不是已批准任务或实验结果。

1. 只从已冻结的 fit501 训练侧抽取最多 24 个任务，固定 seed=42，按“类别、价格、规格、正常零分/预算、部分分、满分”分层。同一任务可有多个标签，但任务 ID 去重；每类目标 4 个，不足则报告实际数量，不从 dev/test 补齐。抽取前公布候选定义、排序方法、清单和 SHA，避免按模型分数挑例。
2. 两人独立检查这批已有原件；先完成证据、可见性和错误类型标注，再查看模型逐步分数。双标只说明人工一致性，不将主观判断包装成真实步级奖励。逐字段报告分歧数、一致率和裁决记录。
3. 交付原件清单、标注旁表、隔离表及汇总表。必填字段齐全、原件哈希匹配、身份与分差可复算、所有分歧有裁决或明确待定，才可形成可供下一轮训练使用的版本。
4. 对已有检查点先做只读诊断：逐类报告选品步分差、总分误差、当前上下文能否支持判断和缺失/超长比例；已看过的 7544 等案例仅作回归。
5. 若建议新训练，另行提交冻结协议：共同起点、输入身份、总预算、停止条件、比较臂、指标和新评估清单。终局损失与排序损失分别记录数值、梯度贡献、训练对分差及曝光量。调整损失权重或增加更新数需要证据，不保证可以解决问题。

采集新的环境分叉或运行 GPU 均不包含在本次文档 PR 的执行授权中；先由负责人确认数据缺口与资源预算，再交 How 执行。

## 6. 划分与评估约束

- 不改动既有 fit/dev/test 文件。旧 dev160 与 #57 已揭分的 64 题应记录为已使用的开发/诊断数据，不能再宣传为针对新方案完全未看的验证集。
- 本轮标注试点仅用训练侧。开发错误可用于诊断和提出假设，但不得未经新协议直接并入训练。
- 后续方案需从未使用且符合隔离规则的候选中预先冻结新评估；先查历史任务 ID、归一化指令/目标重复及使用记录，披露继承 B1 的 SFT 暴露，不能笼统声称从未见过。
- 预留 test200 继续冻结，不用于选数据、选权重、选评分位置或挑参数。
- 评估同时报告覆盖、同分、技术失败和超长缺失，不只报告有效对。主指标与总分门槛应预先确认，保留 fit-only 基线和按任务配对区间。
- 若后续证据仍不支持排序与总分改善，应报告负结果，不能仅以训练集拟合或少数正例放行 PPO。
