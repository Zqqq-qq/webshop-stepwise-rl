## 1. 为什么提出本建议

当前问题是神经评分器能否把任务总分正确归因到购物动作，而非仅能拟合终局总分。终局 MSE 只约束逐步分数之和，不能唯一确定每一步的贡献。数据质量、监督信号和评分时机均可能影响结果，尚不能认定某一项是唯一原因。

截至本次修订，#57 已有 Zqqq-qq 发布的独立 dev 复算记录：53 项载荷哈希、76 条轨迹重建以及三份检查点共 228 条预测的评分位置与共同输入均已核对。32 个方向有效对中，stage126 为 20/32，terminal 与 ranking 均为 21/32，且两组排对的是相同的 21 题。38 对的总分 MSE 分别约为 0.120542、0.126346、0.125994，7544 的打开商品步排序仍反向。复算结论是本轮未通过 PPO 接入验收，可按已完成的负结果归档。本 PR 引用该公开独立复算，不声称 Jun 在此次文档修订中重新执行了模型或原件验收。

## 2. 建议范围和优先级

先做“错误审计＋针对性标注”，不直接大规模删除或改写数据。本 PR 仅增加建议文档；不修改 SFT 数据、PRM 训练输入、划分、模型、损失或 PPO 实现，不申请新增 GPU 训练预算。

| 优先级 | 建议 | 要解决的问题 |
|---|---|---|
| P0 | 追溯样本身份、错误类型和信息可见性 | 区分数据错误、真实购物失败和评分时机问题 |
| P0 | 技术异常隔离、真实负例保留 | 避免将坏日志当负例，或把有价值的失败删掉 |
| P1 | 同前缀分叉与动作位置的证据标注 | 明确比较的动作、可用信息和环境分差 |
| P1 | 分开审计终局拟合与排序信号 | 判断新增排序监督是否实际产生有效梯度和分差 |
| P2 | 小规模训练侧试点后再冻结实验 | 根据结果决定补采样、调整监督或暂不继续训练 |

## 3. 建议标注字段

建议使用独立 JSONL 旁表，通过原始文件 SHA 和轨迹 ID 关联；保留原始数据不覆盖。以下是拟议标注契约，尚不是已支持的训练输入接口。

| 字段 | 内容与约束 |
|---|---|
| schema_version、annotation_id | 标注版本与唯一编号 |
| task_id、trajectory_id、pair_id | 任务、轨迹及可选比较对身份；同一任务多轨迹可分别追踪 |
| source_commit、source_path、source_sha256 | 原件来源与不可变身份；标注表另存自身 SHA |
| split、historical_usage、b1_sft_exposure | 原划分、历史训练/调参/诊断使用记录，以及继承 B1 的 SFT 暴露；未知须明确记录 |
| goal_fingerprint、instruction_fingerprint | 采用冻结脚本归一化；记录脚本版本，检查跨划分重复 |
| error_types | 类别、价格、规格/选项、检索、格式/非法动作、循环/预算、技术异常、其他、无法判断；允许多选 |
| requirement_evidence | 按要求、商品臂及观察时点分别记录要求原文、页面/轮次、证据原文及定位，不把商品名称出现等同于规格满足 |
| judgment_before_click、judgment_after_click | 各时点分别取支持／反证／当前无法判定；后验判断不得覆盖先前判断 |
| first_evidence_at、record_status | 首次支持或反证证据为点击前／点击后／未观察到／原件缺失；记录原件是否完整，区分没有观察到与无法检查 |
| annotator_prior_exposure | 标注者是否预先见过终局标签、模型分数或案例结论；已知、未知及所见内容分开记录 |
| action_turn、action_text、score_token_index | 被评动作、轮次、实际 tokenizer 结束位置；同时注明索引约定和输入 SHA |
| prefix_sha256、branch_input_sha256 | 共享前缀及两臂实际输入；允许动作长度不同，但不能混入下一轮观察 |
| terminal_reward、termination、done、full_success | 保留真实连续终局分、结束原因与购买/满分成功区别，不把 done 当作成功 |
| pair_reward_gap、pair_status | 同环境重放的真实分差；严格不同分、同分、不可比较分别记录 |
| disposition、reason_code | 保留、隔离、待复核及原因；技术异常不得混入正常零分 |
| annotators、adjudication、label_source | 标注者、争议裁决、标签来源；区分人工判断和环境终局分 |

动作索引必须由实际 Qwen 模板与 tokenizer 定位，核对非 padding 的 assistant 结束 token。点击后商品详情属于后续观察，不能偷偷加入点击前评分输入。若比较“看到详情后的判断”，应单独定义评分位置、样本和实验，不能与原动作分数混为同一机制。

终局高低分只表示两条完整轨迹的结果差异，不自动等价于每个中间动作的真实贡献。人工错误类型用于诊断；未经协议确认，不直接变成奖励或步级训练标签。

### 3.1 判定与证据位置分开记录

每项要求、每个商品臂均保留点击前与点击后的独立记录。支持表示当前页面证据支持该项要求；反证表示当前证据与该项要求冲突；当前无法判定表示信息不足。两类字段不能互相代替：证据在点击前出现，不代表足以支持全部规格；点击后才出现的细节只支持后验诊断。

证据引用须包含原文、原件文件 SHA、页面/消息索引及对应轮次。若完整页面里未找到有关信息，首次证据位置填“未观察到”；若页面原件缺失则填“原件缺失”，不能从终局分反推缺失页面包含什么。点击前判定无法完成时保留“当前无法判定”并说明原因。判定变化时保留前后两版证据，不能回填为点击前已知。

任务 1649 可用作**已知终局分的训练侧流程示例**：评审指出两臂环境分为 1.0 / 0.8，但该分差不回答点击前哪条要求可判定。示例仍须由标注者从真实搜索页、动作和后续详情引用证据；本文件没有代填其类别、规格或点击前判断。已读该案例结论者必须记录 prior exposure，不计为对终局标签盲测。示例是否进入正式六题清单以冻结清单为准。

### 3.2 字段来源与缺失约定

| 字段组 | 生成或核对方式 | 人工责任与缺失处理 |
|---|---|---|
| 原件身份、任务/轨迹/比较对 ID、split | 从冻结清单与原归档导入，脚本核 SHA、唯一性和关联 | 关联失败登记 missing 与原因，不编造 ID |
| historical_usage、b1_sft_exposure | 关联历史使用清单及 B1 训练记录，保存依据版本 | 记录不足填 unknown；未知 SFT 暴露不等于未暴露 |
| 指令/目标指纹、前缀与分支输入 SHA | 按冻结脚本复算，记录脚本提交和规范化规则 | 缺少所需原文时标 missing，不用空串哈希代替 |
| 动作、轮次、score_token_index | 从原始轨迹导入，用固定 Qwen 模板/tokenizer 重建；记录零基索引、输入 SHA 与 tokenizer 身份 | Jun 交叉检查对应 assistant 结束 token；失败保留原件并登记原因 |
| 环境分、termination、done、full_success、分差 | 从环境记录导入并按冻结口径复算，不由标注者猜测 | 缺环境记录填 missing；同分不是缺失；不以模型分替代 |
| 错误类型、要求证据、前后判定、首次证据位置 | 两位标注者各自阅读原件并独立填写 | 无法判定、未观察到、原件缺失分别统计；保留两份原始标注 |
| prior exposure、disposition、裁决 | 标注者报告既有知情情况；争议由确认的复核人裁决 | 无共识则 pending，不强行生成一致标签 |
| 标注表身份、计数与一致率 | 标注导出后脚本生成 SHA、任务/轨迹/对数及逐字段统计 | 可见性统计逐要求报告，错误类型按多标签集合报告；同时报告有效分母和缺失数 |

序列化约定：无比较臂的单轨迹使用 pair_status=not_applicable，pair_id、pair_reward_gap、prefix_sha256、branch_input_sha256 为 null，并附字段状态 not_applicable；有比较对但缺原件时使用 missing，不能填 not_applicable。未知暴露使用 unknown；原件齐全但当前证据不能判断使用 cannot_determine。数值缺失不写 0，指纹缺失不写占位哈希。旁表应保存字段状态及 reason，不靠 null 本身推断缺失原因。上述状态属于拟议契约，实际脚本尚待实现和验证。

## 4. 清洗规则

- 保留真实的类别、价格、规格错误和正常 max_steps 失败；它们可能是重要负例。不得为了降低 MSE 删除困难样本。
- 原件损坏、关键观察缺失、重放技术失败、身份不一致、错配比较对和标签矛盾进入隔离表；原件保留，修复或排除理由可审计。
- 同前缀比较对必须核对同一环境身份、共同历史及预定后续动作策略；记录两臂真实终局分。非首个分叉的后续变化也要披露，不能将所有终局差异归因于首次点击。
- 保留 0、部分分与满分的真实环境分；正常预算耗尽的零分不是技术故障；购买结束也可能是零分或部分分。
- 同分对单列，不制造高低标签；无法验证的标签标为未知，不凭模型预测补标签。
- 不截断掉关键动作或结果后仍沿用完整轨迹标签。超长样本单列覆盖情况，处理策略另行预登记。
- 所有保留/隔离记录均有唯一 ID、原因和计数；原始总数应等于各处置类别数之和。

### 5.1 后续拟议：按结果分层的错误审计（尚未执行）

下面规则用于另一轮错误审计，不再覆盖已完成的 P01–P06 成对校准。采用前另行冻结输入、清单、人员与模板；不能据六题配对包声称本轮已按四层抽样。

先用已知结果抽样，后统计错误类型：

采用评审所核 fit501 原始结果分层：满分购买 154 条、部分分购买 292 条、零分购买 26 条、正常步数耗尽 29 条，合计 501 条。这是引用 Zqqq 的评审计数，冻结时仍须按原件重新核对。类别、价格、规格错误可多选，属于**抽样后人工标注**，不作为预先知道的抽样层，也不保证每类恰有四题。

拟议确定性规则：

- 冻结 fit501 的文件 SHA、任务/轨迹去重口径及结果字段映射。按环境分和结束类型定义四层：购买且分数为 1；购买且 0 < 分数 < 1；购买且分数为 0；正常 max_steps。异常值或不一致记录单列待复核，不擅自改成零分层。
- 每层按 SHA256(ASCII("42:" + task_id)) 升序排序，哈希相同以数值 task_id 排序。这里 seed=42 是固定排序盐，不依赖运行时随机数库。
- 第一批六个任务为满分 2、部分分 2、零分购买 1、正常耗尽 1；扩大时各层最多 6 个，总计最多 24 个，六题是扩展清单的子集。
- 抽样单位为去重后的 task_id；同一任务多条原轨迹均保留关联，不重复计题。若同一任务跨结果层，先列为待复核并确认归层规则，不任意选择有利轨迹。某层不足则报告实际数和原因，不从其他层或 dev/test 补足，也不按模型结果换题。
- 分层抽样反映审计覆盖，**不代表总体错误率估计**。试标后报告类别/价格/规格等覆盖和多标签交集，不能把各错误标签数相加冒充任务总数。
- 与 #57 已有 20 个严格分差训练任务、12 个未形成严格分差的候选逐项关联；有原件才做成对审计，无对照仍可做单轨迹审计。没有比较对不是自动剔除理由，也不为达到成对数量重新挑题。
- 标注开始前导出冻结 manifest：候选来源与 SHA、脚本版本、层定义、每层完整排序和入选 ID、原件路径/SHA、配对可用性、短缺或待复核记录。两位标注者使用同一批输入；对 manifest 的变更另存版本并说明原因。

### 5.2 后续双人独立标注与揭示顺序（非本轮完成声明）

1. 从设备原件导出不含终局分、模型预测及高低臂暗示的标注视图，以中性臂名替代 high/low。抽样分层、终局分和既有结论由协调人保存，先不发给标注者；记录标注者 prior exposure，已经知情的案例单列，不能假称盲标。
2. 两位标注者先独立阅读点击前历史及搜索页，引用证据，锁定每项要求的点击前判定；再开放点击后详情，记录新增证据、首次出现位置及后验判定。单轨迹按同样时序检查。
3. 两份标注完成并保存版本/SHA 后，揭示真实环境分和终止原因，核对冲突及错误类型；最后才查看模型逐步分。保留揭示前后版本，不能用结局改写先前的可见性判断。
4. 逐字段报告一致率、有效分母、分歧数及缺失数；错误类型按多标签集合另报。六题仅用于检查口径与工作量，不足以宣称总体标注可靠性或模型改进。
5. 对分歧保留双方原始记录，由确认的复核人给出证据与裁决；未决项保留 pending。先复审六题的字段可用性、判定口径和工时，再决定是否扩至 24 题。

### 5.3 本轮签收边界与后续实验

拟议审计交付并验收的是**可追溯的诊断旁表**：原件/清单、两份独立标注、揭示记录、裁决或待定项、隔离表、覆盖与一致率汇总。原件哈希、身份和环境分差可复算，各处置类别计数守恒；无法判断的记录可以作为有效诊断交付，但须完整登记原因，不能强制填成正负标签。

诊断旁表通过验收**不等于自动获得训练资格**。哪些记录适合作为排序监督、是否需补采、是否改变评分位置及如何生成训练输入，均由后续协议另行确认。类别错误等人工标签也不自动成为步级奖励。

对已有检查点可先做只读诊断：逐类报告选品步分差、总分误差、当前上下文能否支持判断及缺失/超长比例；已看过的 7544 等案例仅作回归。若建议新训练，另行冻结共同起点、输入、预算、停止条件、比较臂、指标和新评估清单。终局损失与排序损失分别记录数值、梯度贡献、训练对分差及曝光量，不能预设增加更新或调权重一定有效。

新环境分叉采集或 GPU 运行不属于本次文档修订；先根据诊断记录确认缺口与资源预算，再交执行人处理。
