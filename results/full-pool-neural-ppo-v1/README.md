# TG 与 Arm 4 全训练池 PPO 对照

本方案取代原 32 题候选对照。执行代码固定为 `01def67412aecd0cc6571a84b4b1d974aece0b40`，数据按本目录的提交另行固定。先在目标 GPU 上完成权重重载、7544 新参考和一次小规模工程更新，确认后直接运行下述全池对照。

## 训练池和预算

以原冻结的 1,451 题 `mapped_train` 为起点。按 [机器清单](manifest.json) 排除 `fit501`、#57 的训练候选、已用开发集、四题短训、冒烟和回归任务，以及 `val160`、`test200`。核对归一化指令孪生和与上述排除集的指令碰撞后有 620 个候选；再对池内仅价格上限不同的同类指令做确定性去重，取 **618 题**。两个 seed 用同一池的不同顺序，每个 seed 内 TG 与 Arm 4 使用同一顺序。

| 口径 | 冻结值 |
| --- | ---: |
| 每个 seed、每臂遍历 | 1 轮、618 条训练轨迹 |
| 每个 seed、每臂更新 | 155 次，154 批各 4 题，尾批 2 题 |
| 两个 seed、两臂合计 | 620 次更新、2,472 条轨迹 |
| 单卡训练时间估算 | 约 40 小时，不含验收、验证、归档和重试 |

耗时按四题短训的 TG 220.6 秒、Arm 4 241.9 秒每次更新线性外推。执行中记录实际交互步数、生成 token、显存峰值、用时和检查点状态。

## 执行与复算

1. 在数据检出运行 `python results/full-pool-neural-ppo-v1/prepare_batches.py --output /path/to/new-batches`。脚本核对拆分和任务顺序 SHA-256、训练集归属以及两个 seed 的池覆盖，生成两个 seed 的批次和 `batch-index.json`。
2. 在执行检出按 [训练与奖励审计命令](../../docs/NEURAL_PPO_COMPARISON.md) 准备两臂。用 seed 42、43，各自从同一 B1 与初始 critic 开跑；Arm 4 保持冻结。每个 seed、每臂按 `batch-index.json` 顺序调用 `webshop-lab ppo-smoke --ids <batch>`，第二批起 `--resume` 上一批已验证输出。每题最多 3 步，生成上限 96，训练 FP32、context 2048、temperature 1、top-p 1、top-k 0、beta 0。失败批次保留日志并从上一份已验证的检查点续跑，避免重抽题。三步上限会限制需要更多步骤的购物，应在汇报时披露；两臂口径保持一致。
3. 四条训练链完成后，四个终点统一评估原冻结 `val160`，FP32 贪心、每题最多 10 步、生成上限 128。按 seed 报告满分成功率和平均环境终局分的逐题配对差及置信区间，同时单列失败但累计神经奖励达到 0.30 的轨迹。保留原始 metadata 和奖励审计。每个 seed 完成一对训练即可归档和先复算该 seed，最终结论使用两个 seed。预留 `test200` 保持冻结。
